# clicker

설명 없이 링크만 공유하는 실시간 공동 클릭 이벤트. 참여자 전원이 하나의
카운터를 공유하고, 20,000회에 도달하면 원통이 깨지며 이벤트가 끝납니다.

GitHub Pages(정적 호스팅) + Firebase Firestore(실시간 공유 데이터) 조합입니다.
빌드 도구 없이 순수 HTML/CSS/JS이며, 저장소를 그대로 배포합니다.

---

## 배포 전 준비 — Firebase 설정 (약 3분)

`config.js`의 `firebaseConfig`가 비어 있으면 앱은 "설정이 필요합니다" 화면만
표시합니다. 아래를 먼저 진행하세요.

1. **프로젝트 생성**
   <https://console.firebase.google.com> → *프로젝트 추가* → 이름 입력 →
   애널리틱스는 꺼도 됩니다.

2. **웹 앱 등록**
   프로젝트 개요 화면의 `</>` (웹) 아이콘 → 앱 닉네임 입력 → *앱 등록*.
   화면에 나오는 `firebaseConfig` 객체를 복사합니다.
   (나중에 다시 보려면: 톱니바퀴 → 프로젝트 설정 → 내 앱 → SDK 설정 및 구성)

3. **`config.js`에 붙여넣기**
   `apiKey`, `authDomain`, `projectId`, `storageBucket`,
   `messagingSenderId`, `appId` 여섯 값을 채웁니다.

4. **익명 인증 켜기**
   빌드 → Authentication → *시작하기* → Sign-in method 탭 →
   **익명** → 사용 설정 → 저장.
   (같은 브라우저에서 새로고침해도 동일한 익명 사용자로 인식되게 해줍니다.)

5. **Firestore 데이터베이스 만들기**
   빌드 → Firestore Database → *데이터베이스 만들기* →
   위치는 `asia-northeast3 (서울)` → 모드는 아무거나 선택
   (다음 단계에서 규칙을 덮어씁니다).

6. **보안 규칙 게시** — 둘 중 하나
   - 콘솔: Firestore Database → *규칙* 탭 → 이 저장소의
     [`firestore.rules`](./firestore.rules) 내용을 통째로 붙여넣고 *게시*.
   - CLI: `npm i -g firebase-tools && firebase login` 후 저장소에서
     `firebase deploy --only firestore:rules`.
     저장소에 `firebase.json`과 `.firebaserc`가 들어 있어 `firebase init`은
     따로 하지 않아도 됩니다.

7. 커밋 후 푸시하면 1~2분 안에 GitHub Pages에 반영됩니다.

> **Firebase Hosting은 쓰지 않습니다.** 페이지는 GitHub Pages가 서빙합니다.
> `firebase deploy`를 옵션 없이 실행하면 호스팅까지 배포되어 링크가 두 개로
> 갈라지니, 반드시 `--only firestore:rules`를 붙이세요.

> **`apiKey`를 공개 저장소에 올려도 되나요?**
> 네. Firebase 웹 `apiKey`는 비밀키가 아니라 프로젝트 식별자입니다.
> 실제 접근 통제는 6번의 보안 규칙이 담당합니다.

## 설정값 (`config.js`)

| 값 | 설명 |
| --- | --- |
| `GOOGLE_FORM_URL` | 완료 화면의 설문 링크. 비우면 "설문 준비 중"만 표시됩니다. |
| `TARGET_CLICKS` | 목표 클릭 수. 기본 20,000. |
| `ADMIN_PASSWORD` | 제작자 통계 화면 비밀번호. 보안이 아니라 오작동 방지용입니다. |
| `GA_MEASUREMENT_ID` | 구글 애널리틱스 4 측정 ID. 비우면 GA를 로드하지 않습니다. |
| `firebaseConfig` | 위 2번에서 복사한 값. |
| `SHARD_COUNT` | 카운터 샤드 수. 이벤트 도중에는 바꾸지 마세요. |

## 제작자 통계 화면

화면 **우측 하단 모서리를 2초 안에 5번** 클릭한 뒤 비밀번호를 입력하면
열립니다. 이벤트 상태, 달성률, 고유 접속자 수, 실제 참여자 수, 참여율,
1인당 평균 클릭, 상위 1명·5명 비중, 구간별 도달 시각, 익명 사용자별
클릭 수와 접속·클릭 시각을 볼 수 있습니다.

**초기화 버튼은 의도적으로 넣지 않았습니다.** 정적 페이지라 앱 코드는
누구나 읽을 수 있어, 앱 안에 초기화 기능을 두면 참여자도 실행할 수
있습니다. 보안보다 데이터 보호를 우선해 규칙 층에서 감소·삭제를 아예
막았습니다. 초기화가 필요하면 Firebase 콘솔에서 `clickEvent/main` 문서와
그 하위 `shards` 컬렉션, `clickUsers` 컬렉션을 직접 삭제하세요.

## 동작 방식과 한계 (솔직한 부분)

**클릭 분산 저장**
Firestore는 문서 하나당 지속 쓰기가 초당 1회 수준입니다. 원본처럼 단일
문서에 트랜잭션으로 쌓으면 동시 접속자가 수십 명일 때 충돌로 카운터가
멈춥니다. 그래서 샤드 20개에 `increment()`로 분산 기록하고, 클라이언트가
전체 샤드를 구독해 합산합니다.

**목표치 정확도**
화면에 표시되는 숫자는 **절대 20,000을 넘지 않습니다**(항상 목표 이하로
클램프). 다만 샤드 방식 특성상 서버 원장 합계는 마지막 순간 동시 전송으로
수십 건 정도 초과 기록될 수 있습니다. 이 경우 통계 화면에
`20,000 (원장 20,0xx)` 형태로 함께 표시합니다. 참여자 경험상 결과는
정확히 20,000입니다.

**낙관적 증가 없음**
서버에 반영된 값만 화면에 표시합니다. 저장 실패 시 해당 클릭은 큐로
되돌아가 재시도되며, 숫자가 올라갔다가 되돌아가는 일은 없습니다.
연결 전에는 클릭이 아예 활성화되지 않습니다.

**어뷰징**
정적 페이지에는 서버가 없어 콘솔로 조작하는 것을 완전히 막을 수 없습니다.
규칙으로 감소·삭제와 1회 200건 초과 기록을 막아두었지만, 작정하고
스크립트를 돌리는 것까지는 방지할 수 없습니다. 사내 이벤트 성격을 고려한
선택입니다.

**구글 애널리틱스**
붙이면 접속자 수, 유입 경로, 기기, 체류 시간을 볼 수 있습니다. 다만
광고 차단기 사용자는 집계되지 않으므로 **정확한 참여 수치는 제작자 통계
화면(Firestore)이 정본**입니다. 클릭은 개별 전송하지 않고
`first_click`, `click_batch`(30초 요약), `milestone`, `event_complete`,
`survey_click`만 보냅니다.

## 로컬에서 확인하기

ES 모듈을 쓰므로 `file://`로 열면 동작하지 않습니다.

```bash
python3 -m http.server 8000
```

이후 <http://localhost:8000> 접속.

## 수집하지 않는 정보

이름, 이메일, 전화번호, IP 주소를 수집하지 않습니다. 참여자는 Firebase
익명 인증이 발급한 식별자로만 구분됩니다.
