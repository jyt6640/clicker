# clicker

설명 없이 링크만 던지는 실시간 공동 참여 이벤트 모음. 다섯 개의 게임이
각각 독립된 링크와 독립된 통계를 가집니다.

GitHub Pages(정적 호스팅) + Firebase Firestore(실시간 공유 데이터) 조합입니다.
빌드 도구 없이 순수 HTML/CSS/JS이며, 저장소를 그대로 배포합니다.

## 게임

| 게임 | 링크 | 방식 | 끝나는 조건 |
| --- | --- | --- | --- |
| 원통 클릭 | `/` | 누를수록 원통에 금이 갑니다 | 20,000회 → 전원 완료 화면 |
| 얼음 녹이기 | `/melt/` | 문지른 거리가 마찰량으로 쌓입니다 | 22,221회 → 마지막 한 명만 암호 문구, 나머지는 Good Job |
| 자물쇠 | `/lock/` | 3자리 다이얼을 맞춥니다 | 개인이 정답을 맞히면 열립니다 |
| 줄다리기 | `/tug/` | 접속 시 두 팀 중 하나에 배정 | 격차 3,000 → 그 팀 승리 |
| 더 버튼 | `/button/` | 누르면 60초 타이머가 되돌아갑니다 | 아무도 안 누르면 0에서 종료, 마지막에 누른 사람이 승자 |

제작자 통계는 `/stats/` 한 페이지에서 다섯 게임을 모두 봅니다.

각 게임 화면에는 서비스 이름, 설명, 사용법, 메뉴, 운영자 정보가 없습니다.
숫자와 오브젝트만 보고 행동하도록 만들어져 있습니다.

## 배포 전 준비 — Firebase 설정 (약 3분)

`config.js`의 `firebaseConfig`가 비어 있으면 앱은 "설정이 필요합니다" 화면만
표시합니다.

1. **프로젝트 생성** — <https://console.firebase.google.com> → *프로젝트 추가*.
2. **웹 앱 등록** — `</>` 아이콘 → 앱 등록 → `firebaseConfig` 복사 →
   `config.js`에 붙여넣기.
3. **익명 인증 켜기** — Authentication → Sign-in method → **익명** → 사용 설정.
   같은 브라우저에서 새로고침해도 동일한 익명 사용자로 인식됩니다.
4. **Firestore 데이터베이스 만들기** — Firestore Database → 데이터베이스 만들기
   → 위치 `asia-northeast3 (서울)`.
5. **보안 규칙 게시** — 둘 중 하나
   - 콘솔: Firestore Database → *규칙* 탭에 [`firestore.rules`](./firestore.rules)
     내용을 붙여넣고 게시.
   - CLI: `npm i -g firebase-tools && firebase login` 후
     `firebase deploy --only firestore:rules`.
     `firebase.json`과 `.firebaserc`가 저장소에 있어 `firebase init`은 불필요합니다.

> **Firebase Hosting은 쓰지 않습니다.** 페이지는 GitHub Pages가 서빙합니다.
> `firebase deploy`를 옵션 없이 실행하면 호스팅까지 배포되어 링크가 두 개로
> 갈라지니 반드시 `--only firestore:rules`를 붙이세요.

> **`apiKey`를 공개 저장소에 올려도 되나요?** 네. Firebase 웹 `apiKey`는
> 비밀키가 아니라 프로젝트 식별자입니다. 실제 접근 통제는 보안 규칙이 합니다.

## 데이터 구조

게임마다 네임스페이스가 완전히 분리되어 통계가 섞이지 않습니다.

```
games/{gameId}                 상태, 시작·종료 시각, 구간별 도달 시각
games/{gameId}/shards/{n}      카운터 샤드
games/{gameId}/users/{uid}     익명 참여자별 기록
```

`gameId`는 `cylinder`, `melt`, `lock`, `tug`, `button` 다섯 개입니다.

이름, 이메일, 전화번호, IP 주소는 수집하지 않습니다. 참여자는 Firebase 익명
인증이 발급한 식별자로만 구분됩니다.

## 설정값 (`config.js`)

| 값 | 설명 |
| --- | --- |
| `GOOGLE_FORM_URL` | 다섯 게임이 공용으로 쓰는 설문 링크. 비우면 "설문 준비 중"만 표시됩니다. |
| `GAMES` | 게임별 목표치·정답 해시·쿨다운 등. |
| `ADMIN_PASSWORD` | `/stats/` 진입 비밀번호. 보안이 아니라 오작동 방지용입니다. |
| `GA_MEASUREMENT_ID` | GA4 측정 ID. 비우면 GA를 로드하지 않습니다. |
| `firebaseConfig` | Firebase 콘솔에서 복사한 값. |
| `SHARD_COUNT` | 카운터 샤드 수. 이벤트 도중에는 바꾸지 마세요. |

## 동작 방식과 한계 (솔직한 부분)

**카운터 분산**
Firestore는 문서 하나당 지속 쓰기가 초당 1회 수준입니다. 단일 문서에
트랜잭션으로 쌓으면 동시 접속자가 수십 명일 때 충돌로 카운터가 멈춥니다.
그래서 샤드 20개에 `increment()`로 분산 기록하고 클라이언트가 합산합니다.

**목표치 정확도**
화면 숫자는 목표를 넘지 않습니다(항상 클램프). 다만 샤드 방식 특성상 서버
원장 합계는 마지막 순간 동시 전송으로 수십 건 초과될 수 있습니다. 통계에
`20,000 (원장 20,0xx)` 형태로 함께 표시됩니다.

**낙관적 증가 없음**
서버에 반영된 값만 화면에 표시합니다. 저장 실패 시 해당 입력은 큐로 되돌아가
재시도되며, 숫자가 올랐다가 되돌아가는 일은 없습니다. 연결 전에는 입력이
활성화되지 않습니다.

**자물쇠 정답 보호는 완전하지 않습니다**
평문 정답은 코드 어디에도 없고 접두사별 솔트 SHA-256 해시만 있습니다.
소스보기나 Ctrl+F로는 정답이 보이지 않습니다. 하지만 세 자리는 경우의 수가
1,000개뿐이라 브라우저에서 전수 대입하면 몇 밀리초 만에 뚫립니다.
**정적 페이지에서 클라이언트 검증으로 정답을 완전히 숨기는 것은 원리적으로
불가능합니다.** 어차피 힌트로 공개될 정답이라는 전제로 설계했습니다.
완전히 막으려면 Cloud Functions(유료 요금제) 같은 서버 검증이 필요합니다.

DevTools를 감지해 멈추는 `debugger` 트랩은 넣지 않았습니다. 우회가 쉬운
데다, 개발자 대상 이벤트에서 참여자 브라우저를 멈추게 만들 뿐입니다.

**어뷰징**
서버가 없어 콘솔 조작을 완전히 막을 수 없습니다. 규칙으로 감소·삭제와 1회
초과 기록을 막아두었지만 스크립트 연타까지는 방지하지 못합니다.
자물쇠에는 힌트를 빨리 열려는 연타를 막는 2초 쿨다운이 있습니다.

**더 버튼의 시계**
남은 시간은 각 참여자 브라우저의 시계로 계산합니다. 시계가 크게 어긋난
기기에서는 표시가 몇 초 다를 수 있습니다.

**구글 애널리틱스**
유입 경로·기기·체류 시간 파악용입니다. 광고 차단기 사용자는 집계되지
않으므로 **정확한 참여 수치는 `/stats/`(Firestore)가 정본**입니다.
입력을 개별 전송하지 않고 `first_action`, `milestone`, `game_complete`,
`survey_click`만 보냅니다.

**초기화**
앱 안에는 초기화 기능이 없습니다. 정적 페이지라 소스가 공개되므로 앱 내
초기화는 참여자도 실행할 수 있기 때문입니다. 규칙 층에서 감소·삭제를 막고,
초기화는 Firebase 콘솔에서 `games/{gameId}` 문서와 하위 컬렉션을 직접
삭제하는 방식으로만 가능합니다.

## 배포할 때

애셋 URL 뒤의 `?v=` 값을 함께 올려 캐시를 무효화하세요. GitHub Pages는
10분간 캐시를 유지하므로, 링크를 뿌린 뒤 낡은 파일을 잡고 있는 참여자가
생기면 이벤트 내내 깨진 화면을 보게 됩니다.

```bash
grep -rl '?v=' --include='*.html' --include='*.js' . | xargs sed -i '' 's/?v=4/?v=5/g'
```
